# 七层防线设计

**每一层都对应一个真实发生过的失效。**

---

## 总览

| 层 | 防的是什么 | 机制 |
|---|---|---|
| 1 | 主进程存活 | 存活检查 + 推送告警 |
| 2 | 监控进程挂了 | 守护进程自动拉起 |
| 3 | 上报进程卡死 | 心跳超时自动重启 |
| 4 | 面板服务挂了 | 自动拉起 |
| 5 | 日志撑爆磁盘 | 归档保留历史（不截断） |
| 6 | 守护进程自己停了 | 读心跳文件，超时告警 |
| 7 | 数据源失效 | 探针验证 + 回退机制 |

---

## 第一层：进程存活检查

**最简单也最必要的一层。**

```bash
# 核心：用 pgrep 判断进程是否存在
if ! pgrep -f "策略进程名" > /dev/null; then
    推送告警 "进程已停止"
fi
```

### 关键设计

- **告警要有节流**：进程挂了会每分钟触发一次，不能每次都推
- **要能区分"首次发现"和"持续未恢复"**

---

## 第二层：守护进程

**监控脚本自己也会挂。**

用 `crontab` 每分钟拉起一次守护：

```cron
* * * * * /path/to/guardian.sh
```

### 守护脚本要做的事

1. 检查主进程是否存在
2. 不存在 → **再确认一次**（避免竞态误判）
3. 确认后拉起
4. 写心跳文件

### ⚠️ 避免重复拉起

如果上一次拉起还在启动中，再次拉起会导致**双进程**。

**做法**：加锁文件（lock file），并在拉起前检查进程列表。

---

## 第三层：心跳机制

**进程在，但卡死了** —— 这种情况存活检查查不出来。

```python
# 被监控的进程定期写心跳
while True:
    write_heartbeat(time.time())
    do_work()
```

```bash
# 外部检查心跳是否过期
if [ $(($(date +%s) - $(cat /path/heartbeat))) -gt 900 ]; then
    重启进程
fi
```

**阈值选择**：应大于正常任务的**最长单次执行时间**。
太小会误杀，太大则失去意义。

---

## 第四层：面板/服务自动拉起

同第二层逻辑，但要注意：

- **服务启动有依赖顺序**（先数据库后应用）
- **启动后要验证真的起来了**，不是只看 "started"

---

## 第五层：日志归档

**不要截断日志。**

```bash
# ❌ 截断：保留最后 1000 行
tail -1000 app.log > app.log.tmp && mv app.log.tmp app.log

# ✅ 归档：保留历史
mv app.log app.log.$(date +%Y%m%d_%H%M%S)
touch app.log
```

### 为什么要归档

出问题时，你要查的是**历史**。
截断正好删掉你最需要的那段。

### 配套：定期清理旧归档

保留最近 N 天，更早的删除或压缩。

---

## 第六层：守护进程自监控

**递归问题：守护进程挂了，谁来管？**

```
主进程 ← 守护进程 ← ??? 
```

### 实际做法：心跳文件 + 外部检查

| 组件 | 职责 |
|---|---|
| 守护进程 | 每次运行写心跳文件 |
| 外部检查（crontab） | 读心跳，超过阈值则告警 |

### ⚠️ 诚实的边界说明

**这一层仍然有个洞：如果外部检查自己也停了，还是没人知道。**

彻底解决需要：
- 双向互查（两个进程互相监控）
- 或第二条独立的告警通道（如另一台机器、另一个推送服务）

**复杂度会明显上升。**

> **实践建议：明确知道自己停在哪一层，以及那一层的盲区是什么。
> 不要假装已经全覆盖。**

---

## 第七层：数据源健康

**实时数据源失效时，系统要能发现并降级。**

### 失效模式

| 模式 | 表现 |
|---|---|
| 连接断开 | 长时间收不到数据 |
| 收到数据但不更新 | 时间戳不推进 |
| 路由变了 | 请求返回异常或空 |
| 静默回退 | 系统自动降级到备用源，但没人知道 |

### 设计要点

1. **区分"数据源失效"和"市场真的没波动"** —— 看时间戳是否推进
2. **回退必须有告警** —— 静默降级是危险的
3. **加探针验证** —— 主动发一个已知请求，确认返回格式正确

```python
# 探针示例
def check_feed():
    ts = 最新数据时间戳()
    if time.time() - ts > 60:
        return "DEAD"       # 明确区分三态
    if ts == 上次时间戳:
        return "STALE"      # 收到但没更新
    return "OK"
```

---

## 一个通用原则

> **每一层防线都要能被验证。**
>
> 「我加了这个检查」不等于「这个检查在工作」。
> 必须**主动制造一次故障**，确认告警真的响了。

实战经验：**真阳性告警 + 真恢复**，这两个都验证过，才算这条防线成立。
