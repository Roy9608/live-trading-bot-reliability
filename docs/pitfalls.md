# 踩过的坑清单

**每条都是真实发生过的。按痛苦程度排序。**

---

## 1. 「假绿灯」——任务日志的 Success 是假的

### 现象

定时任务日志显示执行成功，但实际什么都没发生。

### 根因

包装脚本的最后一条命令是**清理命令**（如 `rm -f temp`）。

清理命令几乎必然成功 → **整个脚本的返回码永远是 0** →
任务调度器判定为成功。

### 为什么危险

**你会在"一切正常"的错觉里过好几周。**

### 判据

> **不要看退出码，要看痕迹。**

```
□ 日志有新增吗？
□ 目标文件的时间戳变了吗？
□ 应该产生的输出存在吗？
```

### 修法

1. 包装脚本的**最后一步**应该是"验证"而不是"清理"
2. 用 `set -e` 让中间步骤失败即退出
3. 显式 `exit 1` 表示失败，不要依赖最后一条命令的返回码

## 2. 双进程打架

### 现象

同一个策略有两个进程在跑，互相干扰，行为诡异。

### 根因

守护脚本拉起的时机不对 —— 上次拉起的进程还在启动中，就又被拉起一次。

### 排查方法

```bash
# 看有几个进程
pgrep -af "进程名" | wc -l
```

### 修法

- 加锁文件（lock file）
- 拉起前先检查进程列表
- 启动脚本内部也加互斥

## 3. 告警「响了但没送到」

### 现象

本地日志显示"告警已发送"，但手机没收到。

### 可能的根因

| 原因 | 表现 |
|---|---|
| Token 过期 | API 返回错误，但异常被吞 |
| 网络超时 | 请求失败，代码没处理 |
| 平台限流 | 静默丢弃 |
| 消息格式错误 | 服务端拒绝 |

### 修法

1. **发送失败必须记录**，不能让异常静默消失
2. **加端到端验证** —— 定期主动发一条测试消息
3. **第二条通道兜底** —— 重要告警走两个渠道

> **判据：「代码调用了发送函数」≠「消息送到了」。**

## 4. 「不知道」被显示成「没有」

### 现象

面板在数据源断开时显示"无持仓"。

### 为什么危险

**"没有持仓"和"不知道有没有持仓"是完全不同的状态，
但在界面上长得一模一样。**

你可能会据此做出错误决策。

### 修法：三态设计

| 状态 | 显示 |
|---|---|
| 有值 | 数值 |
| 真的是 0 | `0` |
| **取不到** | **`未获取` / `N/A` / `—`** |

> **任何监控面板都必须区分这三态。用 0 表示"取不到"是危险的。**

## 5. 日志被截断，关键历史丢失

### 现象

出问题去查日志，发现需要的那段已经被删了。

### 根因

日志轮转策略用了"截断"而非"归档"。

### 修法

见 [defenses.md](defenses.md) 第五层。

> **磁盘很便宜，事后无法追溯很贵。**

## 6. 静默降级

### 现象

系统正在使用备用数据源，但所有人都不知道。

### 为什么危险

备用源的**精度或延迟可能不同** ——
基于它做的判断，前提已经变了。

### 修法

**降级必须产生告警**，不能静默。

```
数据源状态：
├─ 主源正常      → 正常
├─ 已回退到备用  → ⚠️ 告警
└─ 全部不可用    → 🚨 严重告警
```

## 7. 环境变量导致进程异常退出

### 现象

程序启动后立即退出，没有明显报错。

### 根因

某些运行时环境变量（如 `ELECTRON_RUN_AS_NODE`、`NODE_OPTIONS`）
会改变程序的行为模式。

### 修法

启动脚本里**显式清空/设置**关键环境变量，不要依赖继承。

```bash
#!/bin/bash
unset 有问题的变量
export 需要的变量=值
exec 程序
```

## 8. 补丁重复应用 / 锚点失效

### 现象

同一个补丁跑两次，第二次因为找不到锚点而失败，或者把代码改坏。

### 修法

**补丁必须幂等**：

```python
if 目标内容 in 源码:
    应用补丁()
else:
    print("已应用过，跳过")   # 不要报错，也不要重复应用
```

### 配套：离线验证

应用补丁前，先在一个副本上验证结果正确，再应用到实际文件。

## 通用教训

> **自动化系统的失效，绝大多数不是"程序写错了"，
> 而是"某个假设不成立，但没人发现"。**

常见的错误假设：

| 假设 | 现实 |
|---|---|
| 任务成功 = 真的执行了 | 可能只是退出码为 0 |
| 监控在工作 = 有问题会告警 | 监控自己也会挂 |
| 告警发了 = 收到了 | 可能失败在链路上 |
| 显示 0 = 数值是 0 | 可能是取不到 |
| 只有一个进程 | 可能被重复拉起了 |
